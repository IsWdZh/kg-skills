# kg-evidence-govern：可信证据治理

## 输入 / 输出

- 输入：`00-文档台账/`、`00-多模态清单/`、`10-解析文档/`及人工确认记录。
- 输出：`50-知识资产/_证据/证据卡.jsonl`、`证据索引.md`、`冲突与缺口.md`。

生成证据前对账文档台账与`10-解析文档`的唯一文档 ID；原始格式为 Markdown 的文档必须与其他来源文档执行相同的定位、权限、角色和时效治理。

字段契约见 [references/evidence-schema.md](references/evidence-schema.md)。

## 执行步骤

1. 运行 `python scripts/build_evidence_index.py <工作区>`生成段落级证据候选。
2. 为每条证据确认知识角色：`有效依据|上位约束|现状事实|历史材料|实践经验|方法规范|模型建议`。角色只描述知识性质，不含部署视角。
3. 补齐定位器：文件与版本必填；段落、页码、工作表/单元格、表格、图片区域或流程节点至少一种精确定位必填。
4. 登记适用地区、对象、有效时间、访问范围、权威等级、生成方式和置信度。
5. 对同一主题的值、状态或适用范围执行冲突比较；不得静默覆盖旧证据。
6. 将无来源、定位不完整、权限未知、时效未知和角色未确认项写入缺口清单。

## 硬约束

- 原文抽取与人工确认事实可成为证据；模型建议只能作为建议，不能伪装成事实。
- 实践经验必须登记来源地区、适用条件和适用范围。服务时按请求上下文×知识适用范围计算分区：适用命中/跨域参考；跨适用域知识只能进入参考分区，不得作为目标域确定性依据，不得填平缺口。
- 权限过滤发生在检索前；无权证据不得进入提示词、摘要、引用或错误详情。
- 原件、视觉快照、结构化对象和 Markdown 互相引用，任何一种都不能替代原件。

## 发布门槛

事实性证据必须具备有效来源、精确定位、知识角色、适用范围和访问范围。缺任一项只能进入受限试跑。
