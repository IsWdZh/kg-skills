# kg-tagging：业务打标

## 输入 / 输出

- 输入：`10-解析文档/`、`00-文档台账/台账.md`
- 输出：`20-打标结果/词表与标签体系.md`、`文档级打标.md`、`段落级打标/`、`待人工确认清单.md`

## 执行步骤

### 1. 词表先行（人工确认关卡①）

先建 `词表与标签体系.md` 再打标——**所有标签必须出自词表**，词表外新词先登记为`候选`经确认后才可用。词表包含：

- 标签维度表：业务域 / 业务事项（一级）/ 二级事项标签 / 地区 / 适用对象 / 时间属性；
- 二级事项标签按业务组组织（试跑示例：购房类/建修类/租房类/还贷类/销户类/困难类），**每个标签写同义词归一规则**（如"再交易房=存量房=二手住房"），打标时归一到标准词、原词记备注；
- 打标规则：置信度口径（高=标题+正文双证据；中=单一证据；低=推断）、`中`以下进待确认清单。

生成方式：先扫全部文档标题聚类出候选标签 → 抽读代表性文档校正 → 请用户确认（或批处理预填）。

### 2. 文档级打标（全量）

逐文档输出：编号 / 事项 / 二级事项标签（可多个）/ 适用对象 / 置信度 / 备注。效率策略（试跑验证）：

- 标题语义明确的文档凭标题打`高`置信标签，**不必通读**；
- 必须精读的：标题截断/含糊的、综合性政策文件（多标签）、规程类（覆盖全部情形，逐情形列标签）、与他档边界不清的；
- 多主题文件（如"提取政策调整通知"同时涉及提取+贷款）打多标签并在备注注明"多标签综合文件"。

### 3. 段落级打标（仅深治理场景）

只对进入治理的场景相关文档做，按**段落区间**登记（`p017-p027`），加内容类型标签：申请条件/办理材料/提取范围/时限/额度/办理渠道/办理流程/政策依据/特殊规则/共性-网点信息/共性-法规引用。共性段落（多文档重复出现的网点、法条）标 `（共性）`，供场景拆分时归入共性知识。

### 4. 待人工确认清单

登记并给建议处理：重复文档处置、新旧政策并存（潜在冲突）、标签边界不清、内容未逐字核验、文档时效风险（发布超 3 年统一加时效标注决议）。每项有 `状态: 待确认|已确认（按建议）|已否决`。
