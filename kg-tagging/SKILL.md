# kg-tagging：业务打标

## 输入 / 输出

- 输入：`10-解析文档/`、`00-文档台账/台账.md`
- 输出：`20-打标结果/词表与标签体系.md`、`文档级打标.md`、`段落级打标/`、`待人工确认清单.md`

## 执行步骤

运行前按文档 ID 对账`00-文档台账`与`10-解析文档`，递归处理全部解析 Markdown；不得依据`原始格式`排除原生 Markdown 文档。

### 1. 词表先行（人工确认关卡①）

先建 `词表与标签体系.md` 再打标——**所有标签必须出自词表**，词表外新词先登记为`候选`经确认后才可用。词表包含：

- 标签维度表：业务域/知识主题/内容单元类型/知识角色/地区/适用对象/时间/项目/访问范围/来源类型；
- 内容单元类型由工作区词表定义，不是平台固定分类。通用示例：事实、条款、流程、事件、指标、能力、数据、接口、方法、规则、案例片段；具体业务场景按需扩展自己的类型（如业务梳理类场景的事项、需求、场景、改革、采购条款等）。一份文档可多选。
- 知识角色使用`有效依据|上位约束|现状事实|历史材料|实践经验|方法规范|模型建议`，角色只描述知识性质、不含部署视角；角色不确定必须进入待确认清单。
- 主题标签按业务域组织，**每个标签写同义词归一规则**，打标时归一到标准词、原词记备注；业务域、标签和同义词必须来自当前工作区配置，不得写入 Skill 默认值；
- 打标规则：置信度口径（高=标题+正文双证据；中=单一证据；低=推断）、`中`以下进待确认清单。

生成方式：先扫全部文档标题聚类出候选标签 → 抽读代表性文档校正 → 请用户确认（或批处理预填）→ 将确认结果写入`<工作区>/治理参数.json`的`tagging`节点。`scripts/tag_docs.py`只读取该配置，不内置行业词表。

### 2. 文档级打标（全量）

逐文档输出：编号 / 业务域 / 知识主题标签（可多个）/ 适用对象 / 置信度 / 备注。

**核心纪律：标题只能形成候选主标签，不能据此跳过正文。** 标题明确不等于内容单一；通知、规程和综合文件可能在一个标题下包含多个知识主题。因此**每份文档都要看正文，只是看的深度分层**：

- **速扫确认（多数文档）**：凭标题形成候选主标签后，结构性浏览正文（小标题、分条编号、关键数据与主题关键词），确认①主标签成立，②有无夹带其他主题。两项都核对过才给`高`置信；仅凭标题、未经正文确认的最多`中`置信并进待确认清单。
- **逐字精读（高风险文档）**：标题截断/含糊、政策通知、规程类（覆盖全部情形需逐情形列标签）、与他档边界不清的，必须逐字读完。
- **多主题是常态，速扫的首要目的就是查漏**：一旦发现正文涉及标题之外的主题，立即补全标签并记录涉及段落区间。漏标比错标更隐蔽，不能凭标题直接定案。

### 3. 段落级打标（仅深治理场景）

只对进入深治理的场景相关文档做，按段落、表格、单元格、图片区域或流程节点登记内容单元标签。共性内容标`共性`；实践经验类成果同时标`实践经验`、来源地区和适用范围，供服务时按请求上下文×适用范围计算适用命中/跨域参考分区。

### 4. 待人工确认清单

登记并给建议处理：重复文档处置、新旧版本并存（潜在冲突）、标签边界不清、内容未逐字核验和文档时效风险。时效阈值由知识域配置或明确规则决定，Skill 不设置统一年限。每项有 `状态: 待确认|已确认（按建议）|已否决`。
