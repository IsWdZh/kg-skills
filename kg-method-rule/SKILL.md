# kg-method-rule：方法与规则资产

## 输入 / 输出

- 输入：方法规范、历史正反例、评审规则和外部应用响应要求。
- 输出：`50-知识资产/_方法规则/{资产ID}/manifest.yaml`及方法、规则、问题或响应模板文件。

格式见 [references/method-rule-schema.md](references/method-rule-schema.md)。

## 资产类型

- `method`：目标、前置条件、步骤、判断点和完成条件。
- `guidance`：按缺失信息触发的渐进式引导问题。
- `validation_rule`：条件、严重级别、证据要求、例外、修复建议和豁免要求。
- `response_template`：问答、证据包、案例比较、推荐和校验报告的返回 Schema。

## 执行步骤

1. 分配稳定资产 ID 和语义版本，登记适用行业、知识任务、输入、输出、维护人和来源。
2. 将自然语言规则转换为确定性条件或语义审查指令；两者必须明确区分。
3. 为规则补正例、反例、边界例和自动测试。
4. 运行 `python scripts/validate_method_rules.py <资产目录>`。
5. 通过 `kg-coordinate` 后发布；规则升级触发 `kg-impact`。

## 禁止项

不得包含上层应用的阶段状态、任务流转、审批人、表单 CRUD、正式成果模板或自动写回动作。领域方法可以作为知识，但方法执行状态由调用方管理。
