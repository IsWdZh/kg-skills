# 治理工作区数据规范

本工作区采用“治理态事实源、发布态不可变快照、服务态可重建投影”三层结构。支持 Skills 的模型可直接读写治理态；程序和服务优先消费交换态或数据库投影。

## 2. 编码规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 文档 ID | `{来源码}-{三位序号}` | `LZ-003` |
| 段落锚点 | `{doc-id}#p{三位序号}` | `LZ-011#p012` |
| 单元场景 | `{业务域}-{事项}-{两位序号}` | `GJJ-TQ-01` |
| 地区版本 | `{场景编码}/{来源码}` | `GJJ-TQ-01/LZ` |
| 知识资产 ID | `{类型码}-{场景编码}-{地区码}-{序号}` | `QA-GJJ-TQ-01-LZ-005` |
| 知识包版本 | `v{主}.{次}` | `v1.0` |

类型码：`KC`知识块、`QA`问答对、`WK`Wiki章节、`GR`图谱元素、`RULE`图谱规则。

## 3. 解析文档元数据

front matter 使用中文字段：

```yaml
编号: LZ-003
标题: 示例政策
地区: 兰州
机构: 兰州住房公积金管理中心
文档类型: 办事指南
发布时间: 2026-01-01
生效时间: 未知
源文件: 示例.html
源文件哈希: <SHA-256>
内容哈希: <SHA-256>
接入批次: 20260611-001
接入日期: 2026-06-11
来源网址: 未知
访问范围: 公开
责任人: 未指定
完整性: 完整
```

未知值必须写`未知`或`未指定`，不能省略字段。`访问范围`至少支持`公开|内部|受限|未知`。

## 4. 核心对象链路与档位

```text
文档 → 标签 → 全局业务图 → 单元场景 → 地区版本 → 知识资产 → 冻结知识包 → 服务投影 → 对外服务
```

| 档位 | 组合 |
|---|---|
| 轻治理 | 知识块（+问答对） |
| 标准治理 | Wiki + 知识块 + 问答对 |
| 推理治理 | 图谱 + Wiki + 知识块（+问答对） |

任何组合必须含知识块；图谱必须与 Wiki 同配。

## 5. 内容与引用约束

- 每个知识块标原文锚点；问答对引用知识块；Wiki 章节和图谱规则都必须可回溯到知识块和原文。
- 直接图关系的头尾只能是单个已定义实体。联合条件、AND/OR、例外和结论使用规则节点表达。
- 所有人工确认环节显式记录`状态: 待确认|已确认|已否决`。
- 时间统一为`YYYY-MM-DD`；缺失写`未知`并携带时效风险。
- 访问范围和调用方权限必须在检索前过滤，而不是在答案生成后补救。

## 6. 发布与投影

1. 机械与语义校验通过。
2. 人工审核给出生产发布、受限试跑或退回结论。
3. `snapshot_packages.py`冻结版本资产，写逐文件 SHA-256 与包指纹。
4. `export_kb.py`从冻结快照生成 JSONL、SQLite 和 Cypher。
5. `kg-serve`执行发布后验收。

数据库不是编辑入口。需要修正时回到治理态修改、升版本、重新冻结和导出。
