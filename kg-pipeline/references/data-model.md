# 治理工作区数据规范

本工作区采用“原件与治理态知识事实源、发布态不可变快照、服务态可重建投影”三层结构。外部业务对象始终由调用方持有，知识平台只保存外部 ID、业务版本、只读快照、证据映射和回流后的案例知识。

## 2. 编码规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 文档 ID | `{来源码}-{三位序号}` | `SRC01-003` |
| 段落锚点 | `{doc-id}#p{三位序号}` | `SRC01-011#p012` |
| 通用定位器 | `{doc-id}#{类型}:{定位值}` | `SRC01-003#cell:Sheet1!B12` |
| 单元场景 | `{业务域码}-{主题码}-{两位序号}` | `DOM-TOPIC-01` |
| 地区版本 | `{场景编码}/{适用版本码}` | `DOM-TOPIC-01/MAIN` |
| 知识资产 ID | `{类型码}-{场景编码}-{适用版本码}-{序号}` | `QA-DOM-TOPIC-01-MAIN-005` |
| 知识包版本 | `v{主}.{次}` | `v1.0` |
| 证据 ID | `EV-{doc-id}-{locator}` | `EV-SRC01-003-p012` |
| 方法规则 ID | `MR-{类型}-{序号}` | `MR-RULE-001` |
| 案例 ID | `CASE-{行业码}-{序号}` | `CASE-DOM-001` |
| 外部对象映射 | 调用方 + 外部对象 ID + 业务版本 | `caller-a/object-12/v3` |

类型码：`KC`知识块、`QA`问答对、`WK`Wiki章节、`GR`图谱元素、`RULE`图谱规则、`EV`证据、`MR`方法规则、`CASE`案例。

## 3. 解析文档元数据

front matter 使用中文字段：

```yaml
编号: SRC01-003
标题: 示例文档
地区: 示例地区
机构: 示例机构
文档类型: 规范文件
发布时间: 2026-01-01
生效时间: 未知
失效时间: 未知
源文件: 示例.html
源文件哈希: <SHA-256>
内容哈希: <SHA-256>
接入批次: 20260611-001
接入日期: 2026-06-11
来源网址: 未知
访问范围: 公开
密级: 公开
知识角色: 有效依据
来源权威级别: 正式发布
项目: 未关联
版本关系: 当前有效
模型出域策略: 允许|禁止|需审批
责任人: 未指定
完整性: 完整
```

未知值必须写`未知`或`未指定`，不能省略字段。知识角色使用`有效依据|上位约束|现状事实|历史材料|实践经验|方法规范|模型建议|待确认`；角色只描述知识性质，不含部署视角，地域相对性由服务时按请求上下文×知识适用范围计算。

## 4. 核心对象链路与资产组合

```text
原件/多模态表达 → 标签与证据 → 服务单元 → 知识/方法/案例资产 → 冻结知识包 → 服务投影 → 检索/推荐/校验 → 反馈/影响
```

| 资产 | 选择规则 | 主要用途 |
|---|---|---|
| 问答对 | 默认必选 | 高频、稳定、直匹配问题；不承担复杂推理 |
| 知识块 | 默认必选 | 事实、依据、规则、说明片段和来源追溯底座 |
| Wiki | 可选，可单独选择 | 结构化说明、专题知识页、制度口径梳理、成段内容生成支撑 |
| 图谱 | 可选，可单独选择 | 对象关系、条件关系、流程关系、跨成果一致性检查和影响分析 |

按需增配：证据卡（事实和正式服务必配）、案例资产（经验复用）、方法规则（引导和校验）、流程结构（流程知识分析）。这些资产只描述知识服务能力，不改变外部业务对象所有权。

## 5. 内容与引用约束

- 每个知识块标原文锚点；问答对引用知识块；Wiki 章节和图谱规则都必须可回溯到知识块和原文。
- 直接图关系的头尾只能是单个已定义实体。联合条件、AND/OR、例外和结论使用规则节点表达。
- 所有人工确认环节显式记录`状态: 待确认|已确认|已否决`。
- 时间统一为`YYYY-MM-DD`；缺失写`未知`并携带时效风险。
- 访问范围和调用方权限必须在检索前过滤，而不是在答案生成后补救。
- 事实性响应必须引用证据卡；模型建议不得写成事实。服务时按请求上下文×知识适用范围计算分区：适用命中/跨域参考；跨适用域知识只能进入参考分区，不得作为目标域确定性依据，不得填平缺口。
- 推荐固定为候选，校验固定为只读发现；禁止自动写回、业务状态和审批结论。
- 每次外部调用记录`request_id`、`correlation_id`、`external_object_id`、`business_version`和`knowledge_version`。

## 6. 外部业务对象边界

外部对象映射只保存：调用方、对象 ID、对象类型、业务版本、只读快照哈希、关联知识/证据 ID、请求与反馈 ID。不得保存第二套可编辑对象，也不得以知识版本覆盖业务版本。

回流成果只有在审核状态明确后才进入案例治理；草稿只能记录使用反馈。知识变更只生成影响通知，外部应用自行决定是否创建业务修订任务。

## 7. 发布与投影

1. 机械与语义校验通过。
2. 人工审核给出生产发布、受限试跑或退回结论。
3. `snapshot_packages.py`冻结版本资产，写逐文件 SHA-256 与包指纹。
4. `export_kb.py`从冻结快照生成 JSONL、SQLite 和 Cypher。
5. `kg-serve`和`kg-service-harness`执行服务、权限、契约和主数据边界验收。

数据库不是编辑入口。需要修正时回到治理态修改、升版本、重新冻结和导出。

## 8. 工作区治理参数

核心 Skill 不内置行业、地区、机构、来源码、场景词表或数据库前缀。工作区按需提供：

```json
{
  "domain_code": "DOM",
  "projection_prefix": "kg_dom",
  "tagging": {
    "source_levels": {},
    "domains": [],
    "genres": [],
    "region_rules": []
  },
  "applicability_versions": []
}
```

`projection_prefix`只允许小写字母、数字和下划线；未配置时使用通用前缀`kg`。具体场景可在`integrations/`提供配置模板，但核心脚本不得反向依赖任何一个适配包。
