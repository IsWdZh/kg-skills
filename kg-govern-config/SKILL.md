# kg-govern-config：治理方式配置与切换

## 输入 / 输出

- 输入：`30-业务图与场景/单元场景目录.md`、覆盖盘点
- 输出：`40-治理配置/治理方式配置.md`、`治理任务清单.md`、`变更记录.md`

## 三档治理与扩展资产

| 档位 | 组合 | 适用 |
|---|---|---|
| 轻治理 | 知识块（+问答对） | 查材料/时间/渠道等简单事实，低风险 |
| 标准治理 | Wiki + 知识块 + 问答对 | 结构化说明、制度规则解释、高频问答 |
| 推理治理 | 图谱 + Wiki + 知识块（+问答对） | "我能不能办"条件判断，高风险高频 |

硬约束：①任何组合必含知识块（溯源底座）②图谱必与 Wiki 同配（判断须可解释）③问答对只做高频直匹配，不承担推理。

按需求增配：证据卡（事实和正式服务必配）、案例资产（经验复用）、方法规则（引导和校验）、流程结构（流程知识分析）。这些资产不改变上层业务对象所有权。

## 执行步骤

### 1. 四维评估定档（人工确认关卡③）

对每个进入治理的场景评估：问题复杂度 / 预估频率 / 业务风险 / 治理成本承受，写明结论依据，请用户确认档位。

### 2. 地区版本级配置

配置粒度到地区版本（可覆盖场景默认）。**覆盖缺口的地区版本配"降级执行"**：仅产出依据块+服务引导块，并在配置中写明强制服务约束与解除降级触发条件。

### 3. 生成治理任务清单

任务粒度 = 服务单元 × 适用版本 × 资产类型，登记输入、输出、权限和状态。生产顺序：证据 → 知识块/方法规则/案例 → Wiki/图谱/问答 → 服务策略 → 协同校验。

同时生成检索配置、推荐目标 Schema、校验规则集和回流准入策略。配置只描述知识服务，不得包含外部业务工作流、审批或表单操作。

### 4. 变更记录（每次配置变化必记）

记录：时间/对象/变更前后/原因/操作者/关联任务。初始配置的调整（如轻档内增配问答对）、合并决议落地、降级决议都要记。

## 治理方式切换（运营期）

1. 在配置文件登记**升级触发条件**（如"条件判断类问题占比>10%→升级评估""缺口文档补采到位→解除降级"）；
2. 触发后：写变更记录 → 生成重新治理任务（只针对该场景/地区版本，**不重建全局**）→ kg-produce 增量生产 → kg-coordinate 校验 → kg-package 发布新主版本（旧版本保留为回滚点）→ 服务切到新版本。
