# kg-intake：文档接入

## 输入 / 输出

- 上游：kg-normalize 产出的原件、多模态清单和`00-原始MD/`
- 输出：`10-解析文档/{来源码}/{编号}.md`、`00-文档台账/台账.md`、`00-文档台账/文档版本.jsonl`和定位器映射

## 执行步骤

### 1. 结构化解析

**推荐（先归一再接入）**：先由 kg-normalize 产出 `00-原始MD/`，再运行：

```bash
python scripts/parse_docs.py --from-md <工作区目录>
```

旧流程（绕过归一直接解析原始文件）**已弃用**：不产出原件快照、多模态清单和识别质检，抽取逻辑与 kg-normalize 重复维护。仅历史工作区兼容回归可用，必须显式加 `--legacy`：

```bash
python scripts/parse_docs.py --legacy <源文档根目录> <工作区目录>
```

`--from-md` 从 00-原始MD 的 front matter 继承编号/标题/地区/发布时间。运行前必须确认`kg-normalize/scripts/validate_normalization.py`通过；本步只接受`归一完成|已OCR-质检通过|已视觉复核|已人工复核`。发现`待视觉转写|已OCR-待视觉复核|结构识别失败|解析失败`或状态缺失时，必须在写入接入产物前整体退出并退回 kg-normalize。解析要求：

- 递归接入`00-原始MD/`中的全部文本副本，不按原始格式过滤；原始文件本身是`.md`或`.markdown`时与其他格式执行相同的编号、哈希、权限、版本、定位器和台账流程。
- 接入前对账文本副本文档 ID 与`00-多模态清单/多模态清单.jsonl`；任一侧多出、缺失或重复都整体阻断，不能生成不完整台账。

- HTML 优先提取政务正文容器；布局表格跳过，真实数据表转 Markdown 表格。
- DOCX 按段落和表格顺序输出；PDF 按页提取并保留页码标识。
- 每个可独立引用的段落前生成 `[pNNN]` 锚点。
- front matter 除原字段外增加：`失效时间`、`知识角色`、`来源权威级别`、`密级`、`项目`、`版本关系`、`模型出域策略`。未知值不得静默省略。
- `源文件哈希`与`内容哈希`均使用完整 SHA-256，不使用短哈希作为审计依据。
- 来源网址未知写`未知`；访问范围至少取`公开|内部|受限|未知`；不得因缺失而静默省略字段。
- 内容规范化后按哈希去重；重复文档标明主文档。新旧文件不得仅去重，还要登记`替代|修订|并行有效|冲突`版本关系。
- 段落锚点关联多模态定位器；涉及表格和流程时保留页码、工作表/单元格、表格/图编号、图片区域或流程节点。

### 2. 解析结果体检

以下异常未处理前不得进入打标：

- 段落数极少但字数很多：通常是布局表格或换行解析失败。
- 字数少于 100：通常是图片型网页或扫描页。
- 标题、字数或哈希高度相似：人工核对是否重复或新旧版本。
- 来源网址、发布时间、访问范围缺失：进入待确认清单，并在后续服务中携带时效或权限约束。

### 3. 图片型文档（已在上游处理）

图片型/扫描型文档的 OCR/视觉转写已**前移到 kg-normalize（格式归一）环节**完成——进入本步时 `00-原始MD/` 已全部是完整 md，本步无需再做视觉转写。
- 只有归一验收通过的图片型文档才能接入；OCR 有文字但仍待视觉复核，同样属于阻断状态；
- OCR、视觉和人工复核记录由 kg-normalize 保存在识别质检报告，本步只继承结果和定位器，不重新裁决识别差异。

### 4. 重建台账

人工修订解析文档后运行：

```bash
python scripts/rebuild_registry.py <工作区目录>
```

脚本兼容中文字段和旧版英文字段，但新产物只写中文字段。重建后抽查编号、地区、发布时间、格式、完整性和去重结果，防止元数据被空值覆盖。

## 发布门槛

解析完成只代表“已接入”，不代表来源已核验。缺来源、知识角色、访问范围、责任人、有效时间或精确定位器的文档可以进入受限试跑，但必须进入待确认清单；生产发布前完成补录或书面豁免。
