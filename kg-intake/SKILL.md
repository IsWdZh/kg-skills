# kg-intake：文档接入

## 输入 / 输出

- 上游：kg-normalize 产出的 `00-原始MD/`（格式归一后的统一 md 原料）；亦兼容直接读原始文件目录
- 输出：`10-解析文档/{来源码}/{编号}.md`（带 `[pNNN]` 锚点）、`00-文档台账/台账.md`

## 执行步骤

### 1. 结构化解析

**推荐（先归一再接入）**：先由 kg-normalize 产出 `00-原始MD/`，再运行：

```bash
python scripts/parse_docs.py --from-md <工作区目录>
```

兼容旧流程（直接从原始文件解析，跳过归一环节）：

```bash
python scripts/parse_docs.py <源文档根目录> <工作区目录>
```

`--from-md` 从 00-原始MD 的 front matter 继承编号/标题/地区/发布时间。**上游 kg-normalize 已对图片型文档完成 OCR/视觉转写**，本步把它们当作正常 md 处理；若发现仍标"待视觉转写"，说明归一未完成，应退回 kg-normalize 补全。解析要求：

- HTML 优先提取政务正文容器；布局表格跳过，真实数据表转 Markdown 表格。
- DOCX 按段落和表格顺序输出；PDF 按页提取并保留页码标识。
- 每个可独立引用的段落前生成 `[pNNN]` 锚点。
- front matter 统一使用：`编号`、`标题`、`地区`、`机构`、`文档类型`、`发布时间`、`生效时间`、`源文件`、`源文件哈希`、`内容哈希`、`接入批次`、`接入日期`、`来源网址`、`访问范围`、`责任人`、`完整性`。
- `源文件哈希`与`内容哈希`均使用完整 SHA-256，不使用短哈希作为审计依据。
- 来源网址未知写`未知`；访问范围至少取`公开|内部|受限|未知`；不得因缺失而静默省略字段。
- 内容规范化后按哈希去重；重复文档在台账标明主文档，不重复生产知识资产。

### 2. 解析结果体检

以下异常未处理前不得进入打标：

- 段落数极少但字数很多：通常是布局表格或换行解析失败。
- 字数少于 100：通常是图片型网页或扫描页。
- 标题、字数或哈希高度相似：人工核对是否重复或新旧版本。
- 来源网址、发布时间、访问范围缺失：进入待确认清单，并在后续服务中携带时效或权限约束。

### 3. 图片型文档（已在上游处理）

图片型/扫描型文档的 OCR/视觉转写已**前移到 kg-normalize（格式归一）环节**完成——进入本步时 `00-原始MD/` 已全部是完整 md，本步无需再做视觉转写。
- 若某图片型文档归一状态仍为"待视觉转写"（OCR 引擎缺失且未用大模型视觉补全），台账会标"图片型-未转写（需回 kg-normalize 补全）"，应退回上游补全后再接入；
- OCR 结果中关键数字/表格"以原图复核"的提示由 kg-normalize 在正文内保留，本步原样保留。

### 4. 重建台账

人工修订解析文档后运行：

```bash
python scripts/rebuild_registry.py <工作区目录>
```

脚本兼容中文字段和旧版英文字段，但新产物只写中文字段。重建后抽查编号、地区、发布时间、格式、完整性和去重结果，防止元数据被空值覆盖。

## 发布门槛

解析完成只代表“已接入”，不代表来源已核验。缺来源网址、访问范围、责任人或关键章节的文档可以进入试跑，但必须进入待确认清单；生产发布前按风险等级完成补录或书面豁免。
