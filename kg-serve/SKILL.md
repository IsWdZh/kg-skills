# kg-serve：对外服务

## 输入 / 输出

- 输入：`60-知识包/`（只读当前有效版本的冻结快照）、`80-知识库导出/`（可选服务投影）、`30-业务图与场景/单元场景目录.md`
- 输出：带引用的答案或标准知识服务响应；`70-服务运行/调用记录/`日志

## 服务流程（每问必经）

```
①意图识别（检索/问答/条件判断/跨地区对比/案例/推荐/校验/范围外）
→ ②场景路由（对照单元场景目录，取最具体场景）
→ ③维度识别（地区/对象/时间；政策类问题缺地区必须补问，不得给泛化答案）
→ ④查发布记录定位当前有效版本知识包
→ ⑤校验发布级别、访问范围、时效与包指纹，再按包清单"调用顺序"选形态
→ ⑥调用 kg-context-retrieve 组装证据；推荐调用 kg-recommend；只读校验调用 kg-verify
→ ⑦生成回答或标准响应：结果 + 解释 + 引用 + 适用范围 + 冲突/缺口
→ ⑧登记调用日志（请求/关联ID、调用方、外部对象、业务/知识版本、权限过滤、降级）
```

## 形态调用规则

| 意图 | 调用链 |
|---|---|
| 高频固定问 | 问答对.md 标准问+相似问法匹配 → 命中即用标准答案 |
| 事实查询 | 问答对 未命中 → 知识块.md 检索作答 |
| 流程/解释 | Wiki页.md 章节 → 知识块 补证据 |
| 条件判断 | 知识图谱.md 规则逐条匹配用户条件（缺要素先反问）→ 结论；Wiki页 解释；知识块 溯源；**主动暴露例外分支** |
| 跨地区对比 | 同场景多地区版本并行调取 → 统一维度（范围/条件/材料/时限/额度）对齐差异表，**每行带来源** |
| 案例参考 | 案例片段 → 适用条件/差异/风险 → 底层证据；跨适用域案例单独进入跨域参考分区 |
| 候选建议 | 证据包 + 方法规则 → `kg-recommend`；只返回 suggestion |
| 外部快照校验 | 规则集 + 证据映射 → `kg-verify`；只返回 findings |

## 强制约束

1. **引用强制**：无来源的内容不输出。引用须显示「资产ID + 原始文件名/标题 + 文档锚点」——编号仅作内部定位，对外必须展示文件名/标题。**最可靠来源是资产 `来源` 字段已内联的〔原始文件标题〕——直接照抄、不得删简为纯编号**；资产未内联标题时，再从冻结包「来源文档」映射表解析（只读本包，不依赖工作区台账）；旧格式包无映射表时回查 00-文档台账/台账.md。引用共性知识时，对外引用落到其底层源文档编号+锚点；`CK-*` 仅是内部归类，不单独作为对外引用。
2. **缺适用范围补问**：当知识结论受地区、机构、对象或时间版本影响时，先补齐对应上下文，再路由适用版本；补问文案由当前知识域配置。
3. **降级阶梯**：形态不足（轻档遇判断题）→按知识块答+明示局限；场景在目录但未治理→告知未治理+共性层面依据+引导渠道；缺口包→严格执行包内服务约束（不编造细则）；目录外→拒答并说明范围。
4. **冲突提示**：命中冲突标注的知识，答案必须含处置口径（"新政优先，X 待核实"）。
5. **时效提示**：来源超 3 年或未知 → 答案附核实建议。
6. **不予情形**：命中"不予办理"类共性知识直接告知不可办+依据+相邻可办场景指引。
7. **权限强制**：调用方无权访问的来源、知识块或包不得进入检索上下文，也不得通过引用、摘要或错误信息泄露。
8. **投影可替换**：SQLite/FTS、PostgreSQL、pgvector、Neo4j 仅用于检索和计算；最终答案必须回到冻结包中的资产与锚点核验。中文关键词检索优先 FTS5 trigram；语义问题经评测确有召回缺口时再使用向量检索，并保持结构化过滤先于向量召回。
9. **主数据边界**：不得创建或修改外部业务对象、推进业务阶段、给出审批结论或输出自动写回指令。
10. **角色与适用分区**：回答或响应按知识角色（有效依据、上位约束、现状事实、历史材料、实践经验、方法规范、模型建议）明确分区，并按请求上下文×知识适用范围计算适用命中/跨域参考；跨适用域知识只能进入参考分区，不得作为目标域确定性依据，不得填平缺口。

## 服务验收（首次启用或新版本发布后执行）

设计测试问题集覆盖全部分支：直匹配/事实查询/图谱推理/缺地区补问/冲突提示/缺口降级/跨地区对比/未治理降级/不予情形（各≥1 题），逐题按协议执行并落盘完整轨迹（路由过程+调用形态+答案+引用+验收结论）。全部通过方可对外。
