# kg-service-harness：服务试跑

## 输入 / 输出

- 输入：`integrations/{集成名}/`、冻结知识资产和测试夹具。
- 输出：`70-服务运行/集成测试/{集成名}/`中的契约、黄金、权限和边界报告。

运行：

```bash
python scripts/run_harness.py <集成配置目录> --output <报告目录>
```

## 必测内容

1. 请求和响应符合 Schema，版本、请求 ID、关联 ID、外部对象 ID 可追踪。
2. 无权文档不进入结果、引用、调试轨迹和错误详情。
3. 知识角色与适用命中/跨域参考分区明确；跨适用域知识只出现在参考分区，不作为目标域确定性依据。
4. 推荐与校验不包含自动写回、业务状态变更或审批结论。
5. 草稿回流被拒绝进入共享案例；重复回流保持幂等。
6. 知识换版可生成外部对象影响通知，但不修改外部对象。
7. 至少两个对象模型不同的上层应用夹具使用同一核心契约通过，证明接口不依赖某一应用的专有字段。

## 结论

任何权限泄漏、无来源事实、双主数据写入或业务越权均为阻断项。测试通过只证明知识服务契约可用，不代表上层业务流程已验收。
