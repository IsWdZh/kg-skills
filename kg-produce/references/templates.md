# 四形态文件模板

> `{SU}`=知识服务单元编码（如 DOM-TOPIC-01），`{AV}`=适用版本码，`{DOC}`=编号。资产 ID 规则：`{类型码}-{SU}-{AV}-{三位序号}`，类型码 KC/QA/WK/GR。

## 1. 知识块.md（知识块）

```markdown
# 知识块库：{SU}/{AV}（服务单元名 / 适用版本名）

> 治理档位: 轻|标准|推理 | 生产时间: YYYY-MM-DD | 来源文档: {DOC}（时效说明）

## KC-{SU}-{AV}-001
- 类型: 事实|条款|条件|输入|过程|输出|指标|规则|例外|冲突标注|依据|服务引导
- 适用范围: 地区=…；对象=…（；时效=… 仅当与文档整体不同时标注）
- 内容: ＜忠实原文的完整规则，数字逐字照抄＞
- 来源: 〔{标题}〕{DOC}#pNNN（每个文档锚点前置〔原始文件标题〕，标题取自 00-文档台账/台账.md，使对外引用无需查表即显示文件名；可多个、可区间 #pNNN-pNNN；引用共性知识时注"详见 CK-<业务域码>-<序号>"）
```

## 2. 问答对.md（问答对）

```markdown
# 问答对库：{SU}/{AV}（服务单元名 / 适用版本名）

> 定位：高频问题直接匹配标准口径，不承担复杂推理。（时效提示，如适用）

## QA-{SU}-{AV}-001
- 标准问: ＜用户原话风格＞
- 相似问法: ＜2-3 个变体，｜分隔＞
- 标准答案: ＜只重组知识块内容；含冲突时附处置口径；时效风险附核实提示＞
- 适用范围: 地区=…；对象=…
- 来源: KC-{SU}-{AV}-00X（{DOC}#pNNN）
```

## 3. Wiki页.md（结构化业务说明页）

```markdown
# {场景名} / {地区名}版本

> Wiki 状态: 已生成待审|已审核|已发布 | 发布版本: v… | 生产时间: … | 数据时效: …（冲突合成说明，如适用）

## 适用对象
＜一句话+特殊人群＞ 来源: KC-…

## 办理条件
＜前置条件+情形条件，编号列出＞ 来源: KC-…（判断逻辑见 知识图谱§RULE-XX，推理档时）

## 所需材料
＜分路径/分情形列出，替代件规则用粗体标注＞ 来源: KC-…

## 关键规则 / 时效要求
＜规则差异用表格；冲突用⚠️行内标注＞ 来源: KC-…

## 办理渠道 / 办理流程
＜引用共性知识 CK-<业务域码>-<序号>＞

## 特殊规则与注意事项
来源: KC-…

## 来源依据
- 《文件名》（文号，日期）→ {DOC}
```

## 4. 知识图谱.md（知识图谱：实体/关系/规则）

```markdown
# 知识图谱：{SU}/{AV}（服务单元名 / 适用版本名）

> 职责：表达对象、关系、条件与规则，支撑判断；结论须经 Wiki 解释、知识块溯源。

## 1. 实体
| ID | 实体 | 类型(对象|标的|凭证|属性|约束对象) | Wiki 锚点 |

## 2. 关系
| ID | 头 | 关系 | 尾 | 来源 |

## 3. 规则
### RULE-{RG}-01 ＜规则名＞
- IF ＜条件，可 AND/OR＞
- THEN ＜结论/额度计算式＞
- EXCEPT ＜例外分支，如有＞
- 附加: ＜材料要求等附随义务＞
- 来源: KC-{SU}-{AV}-00X

## 4. 判断流程
＜mermaid flowchart：决策节点与 RULE 编号一一对应，含拒绝/降级出口＞
```

## 5. 共性知识库（_共性知识/共性知识库.md）

```markdown
## CK-{DOMAIN}-NNN ＜名称＞
- 适用范围: ＜复用到哪些服务单元/适用版本＞
- 时效: …
- 来源: {DOC}#pNNN
＜内容：表格或编号清单＞
```
首部声明：共性知识用于治理复用与服务支撑，**不能脱离其底层证据直接作为事实性对外答案**。
