# kg-normalize：多模态格式归一

## 定位

治理流程的**第 0 环节**：原件是审计事实源，Markdown 只是检索副本。为同一文档建立原件、视觉快照、结构化对象和文本副本四种关联表达；图片型/扫描型文档的文字识别也在本环节完成。

## 输入 / 输出

- 输入：按来源/地区分组的源文档目录、本次工作区目录
- 输出：`00-原始资料/`原件快照、`00-原始MD/`文本副本、`00-视觉快照/`、`00-结构化对象/`和`00-多模态清单/多模态清单.jsonl`

## 执行

如需指定来源码、地区和机构，在源目录放置`source-map.json`；未配置的子目录会自动分配来源码。单趟归一同时产出原件快照、视觉资产、结构化对象、文本副本、识别质检和多模态清单：

```bash
python scripts/normalize.py <源文档根目录> <本次工作区目录>
python scripts/record_visual_review.py <本次工作区目录> <文档ID> --status 已视觉复核 --review-file <复核结果.json>
python scripts/validate_normalization.py <本次工作区目录>
```

旧入口`to_markdown.py`和`build_multimodal_bundle.py`保留为兼容 shim，均委托单趟归一。重跑幂等：已复核（`已视觉复核|已人工复核|结构识别失败`）的文档不会被重新生成覆盖。

**按需物化策略**（清单`layout_version: 2`，路径一律相对工作区）：

- 图像只存一份，统一在`00-视觉快照/{doc-id}/`（内嵌图`image-NNNN`、PPT 图`slide-NNNN-image-NNNN`、图片型 PDF 页`page-NNNN.png`）；`00-原始MD`不再存图片；
- 纯文本文档的结构化对象为 stub（清单`structured_level: stub`）；DOCX 只存表格（含`grid_span`/`v_merge`合并信息）和图像引用，不重复存正文段落；
- 文本型 PDF 不整页渲染，仅登记`page_count`和逐页`text_blocks`坐标；页面快照按需补渲染；图片型 PDF 渲染一次供 OCR 与复核共用；
- 识别质检报告仅在发生 OCR/视觉识别时生成；纯文本文档的归一状态以清单和 front matter 记录；
- 视觉资产是否必需由清单`visual_required`登记，跳过必须写`visual_skip_reason`，用于区分“正常跳过/应生成但缺失/生成失败”。

- **docx / html / pdf / xlsx / pptx / 图片**：生成可检索文本；表格保留工作表、单元格、合并关系，PDF 保留页码与页面快照，图片保留坐标或整图定位。
- **md / markdown（已有 Markdown 文件）**：直通处理——保留正文结构，继承已有 front matter 中可识别的来源、权限、角色和版本字段，再补充统一元数据与文档编号；归一状态直接标记为`归一完成`，无需格式转换或 OCR。短 Markdown 不得因字数少被误判为图片型文档；原件照常保存到`00-原始资料/`并计算 SHA-256。
- **输入发现完整性**：同时扫描源根目录直接文件和来源目录内任意层级子目录；`source-map.json`未覆盖的位置自动分配稳定来源码。`.md`/`.markdown`与其他格式进入同一来源清点，不得因已经是文本格式而跳过原件、多模态清单或接入台账。
- **图片型 / 扫描型文档**（正文承载于内嵌图片、文字层 < 100 字）：先调用离线 OCR 获取文字、坐标和置信度，再执行质量与复杂度路由；OCR 非空不等于识别通过。
  - `已OCR-质检通过`：普通连续正文，OCR 质量门通过，且没有复杂结构或关键字段风险；
  - `已OCR-待视觉复核`：OCR 有结果，但低置信文字比例、版面结构或风险字段触发复核；必须在本环节用大模型视觉逐图核对并补全；
  - `待视觉转写`：OCR 引擎不可用或没有有效文字；必须用大模型视觉完成转写；
  - `已视觉复核` / `已人工复核`：转写及结构复核完成，可进入接入；
  - `结构识别失败`：复杂表格、流程或图形结构仍无法确认，阻止进入下游。
- **大模型视觉触发条件**：OCR 不可用或无结果、OCR 质量门未通过、复杂表格/流程图/架构图/印章/竖排或多栏版面、金额/日期/编号/比例等关键字段、OCR 与原生结构或第二识别结果冲突。视觉能力不是仅在 OCR 未安装时使用。
- 多页扫描件逐页 OCR；质量报告保存到`00-识别质检/{文档ID}.json`，逐图记录文字框、置信度、风险原因、识别状态和复核信息。
- 视觉/人工复核后先修正文本副本和结构化对象，再用`record_visual_review.py`登记复核方式、时间、说明和未解决项；该脚本只登记审计结果，不替代实际复核。
- 质量阈值只是触发复核的工程门槛，不代表事实正确。默认阈值可由`KG_OCR_MEAN_CONFIDENCE`、`KG_OCR_P10_CONFIDENCE`和`KG_OCR_LOW_CONFIDENCE_RATIO`调整，并应使用本单位样本校准。
- 为每份原料分配文档编号（`来源码-三位序号`），写 front matter（编号/标题/地区/机构/原始格式/源文件/发布时间/字数/内嵌图片/归一状态）。
- 转换清单汇总每份文件的格式/字数/图片数/归一状态，并统计图片型已识别份数。

## 安装 OCR（首次，可选）

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple rapidocr-onnxruntime
```
模型随包内置，离线可用、无需联网。不安装时走大模型视觉转写路径；即使已安装，复杂结构、关键字段和低质量结果仍必须走视觉复核。

## 复杂对象验收

- **原生表格**：优先使用 XLSX/DOCX 的单元格、合并关系和公式等结构化结果，页面图片只用于视觉核对；不得以 OCR 覆盖原生结构。
- **图片表格**：检查行列数、表头层级、合并单元格、文字所在单元格、序号连续性、必填空值及合计/比例关系；关键单元格执行双重识别或人工复核。
- **流程图/架构图**：输出`nodes/edges/lanes/conditions/unresolved_items`，检查节点文字、连线方向、分支标签、起止节点、孤立节点、断链、错误闭环和泳道责任；仅转成一段 Markdown 不算完成。
- **关键字段**：金额、日期、编号、比例、印章文字等必须逐项对照原图；视觉模型与 OCR 不一致时保留差异并转人工裁决，不得静默选择其一。

## 与 kg-intake 的衔接

本环节产出忠实原件和多表达副本；仅当`validate_normalization.py`通过后，kg-intake 才能以 `--from-md` 读取，加锚点、算 SHA-256、完整性体检、去重并建台账。完整数据流：

```
原始异构文件（含已有 Markdown） → 原件快照 + 视觉快照 + 结构化对象 + 文本副本 → kg-intake → kg-evidence-govern
```

## 纪律

- 忠实归一：不增删内容、不做业务判断、不改写数字与表述；原件计算完整 SHA-256；
- **图片识别（OCR/视觉）必须在本环节完成，不得把`待视觉转写`、`已OCR-待视觉复核`、`结构识别失败`或`解析失败`传给下游**；OCR 结果必须保留原图定位和识别质量报告；
- 允许进入下游的状态仅为`归一完成|已OCR-质检通过|已视觉复核|已人工复核`；复杂表格和流程图不能仅凭 OCR 置信度自动通过；
- 任一派生表达必须带文档 ID、原件哈希、定位器和生成方式；解析失败显式登记，不能只保留空 Markdown；
- 进入`kg-intake`前必须满足：受支持源文件数 = 文本副本数 = 多模态清单唯一文档数，且每个文档同时存在原件快照与结构化对象（stub 亦可）；`visual_required`的文档必须有视觉资产，识别链路状态的文档必须有识别质检记录；任何应有而缺失均阻断；
- 编号一经分配，后续环节沿用，不重新编号；
- 每次独立运行用带时间戳的工作区目录（如 `治理演示-YYYYMMDD-HHMM/`），与其他批次隔离。
