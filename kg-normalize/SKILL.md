# kg-normalize：格式归一（统一转 md，含图片 OCR）

## 定位

治理流程的**第 0 环节**：把各种格式的原始文件先"数字化归一"成统一的纯文本 Markdown。**图片型/扫描型文档的文字识别也在本环节完成**——确保进入 kg-intake 时，所有文档已是完整 md，下游不再处理任何非文本格式。

## 输入 / 输出

- 输入：按来源/地区分组的源文档目录、本次工作区目录
- 输出：`<工作区>/00-原始MD/{来源码}/{编号}.md`（全部为完整 md）、`00-原始MD/转换清单.md`、图片导出至 `00-原始MD/_图片/`

## 执行

修改 [scripts/to_markdown.py](scripts/to_markdown.py) 复用的 `parse_docs.SOURCE_MAP` 后运行：

```bash
python scripts/to_markdown.py <源文档根目录> <本次工作区目录>
```

- **docx / html / pdf**：复用 parse_docs 的 `extract_html`/`extract_docx`/`extract_pdf` 抽取文字层，零重复逻辑。
- **图片型 / 扫描型文档**（正文承载于内嵌图片、文字层 < 100 字）：本环节即调用**离线 OCR**（rapidocr-onnxruntime，自带模型、离线可用）逐图识别为文字写入 md，归一状态记 `图片型-已OCR识别`。
  - OCR 引擎未安装时，降级为"导出图片 + 标注待视觉转写"，需在本环节用**大模型视觉能力**逐图转写补全（数字/表格/印章/竖排逐字复核）后再进入接入；
  - 多页扫描件（如 30 页规程）逐页 OCR，耗时随页数增加（约 2-5s/页）。
- 为每份原料分配文档编号（`来源码-三位序号`），写 front matter（编号/标题/地区/机构/原始格式/源文件/发布时间/字数/内嵌图片/归一状态）。
- 转换清单汇总每份文件的格式/字数/图片数/归一状态，并统计图片型已识别份数。

## 安装 OCR（首次，可选）

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple rapidocr-onnxruntime
```
模型随包内置，离线可用、无需联网。不安装时走大模型视觉转写路径。

## 与 kg-intake 的衔接

本环节产出"忠实原文、全部为 md"的原料；kg-intake 以 `--from-md` 读取，加 `[pNNN]` 锚点、算 SHA-256、完整性体检、去重、建台账。完整数据流：

```
原始异构文件(docx/html/pdf/图片) → (kg-normalize：转文字 + 图片OCR/视觉) 00-原始MD/(全部md) → (kg-intake --from-md) 10-解析文档/
```

## 纪律

- 忠实归一：不增删内容、不做业务判断、不改写数字与表述；
- **图片识别（OCR/视觉）必须在本环节完成，不得把未识别的图片型文档传给下游**；OCR 结果在正文内保留"以原图复核"提示；
- 编号一经分配，后续环节沿用，不重新编号；
- 每次独立运行用带时间戳的工作区目录（如 `治理演示-YYYYMMDD-HHMM/`），与其他批次隔离。
