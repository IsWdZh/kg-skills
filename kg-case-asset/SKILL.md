# kg-case-asset：案例与经验资产

## 输入 / 输出

- 输入：`50-知识资产/_回流批次/`中审核状态明确的成果、证据卡和项目元数据。
- 输出：`50-知识资产/_案例/{案例ID}/案例清单.json`、`复用片段.jsonl`、`证据映射.jsonl`、`案例说明.md`。

清单字段见 [references/case-schema.md](references/case-schema.md)。

## 执行步骤

1. 运行 `python scripts/validate_case.py <案例清单.json>`检查准入条件。
2. 登记背景、目标、地区、行业、组织层级、时间、成熟度、审核状态和访问范围。
3. 将输入事实、诊断、设计、实施、评审、返工和最终结果拆成可独立复用片段。
4. 每个片段关联证据、适用条件、不适用条件、地区差异、效果与风险。
5. 记录建议被采纳、修改或否决的原因；被否决方案可作为反例，但不得标为最佳实践。
6. 交 `kg-coordinate` 校验后由 `kg-package` 冻结发布案例版本。

## 硬约束

- 仅接收`已审核|已发布|已确认可沉淀`成果；草稿和在办业务版本不得进入共享案例。
- 案例版本属于知识平台，原项目工作版本和审批状态仍属于外部业务系统。
- 案例服务时按请求上下文×案例适用范围计算分区：适用命中/跨域参考；跨适用域案例只生成候选参考，复用前必须按目标域政策、职责、流程、系统和数据条件执行适配比较，不得作为目标域确定性依据。
- 案例不得包含无权传播的原始材料；脱敏不能替代授权。
