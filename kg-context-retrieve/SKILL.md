# kg-context-retrieve：上下文检索

## 输入 / 输出

- 输入：标准请求 JSON、冻结知识包或服务投影、调用方权限声明。
- 输出：证据包 JSON，包含有效依据、上位约束、现状事实、实践经验、方法规则、跨域参考、冲突、缺口和检索轨迹。

请求响应格式见 [references/retrieval-contract.md](references/retrieval-contract.md)。本地试跑：

```bash
python scripts/retrieve_context.py --request request.json --index evidence.jsonl --output response.json
```

## 检索顺序

1. 校验调用方、请求 ID、关联 ID、权限、地区、时间和外部对象版本。
2. 在召回前按访问范围、项目、组织、密级和模型出域策略过滤。
3. 分别召回有效依据、上位约束、已确认现状事实、方法规则和实践案例。
4. 按权威性、适用性、时效、证据完整度、文本相关性和案例相似度重排。
5. 按请求上下文×知识适用范围计算分区：适用命中/跨域参考；跨适用域知识只能进入参考分区，不得作为目标域确定性依据；冲突和缺口不得被低优先级或跨域参考内容填平。
6. 返回实际使用的知识版本、过滤统计、召回轨迹和降级原因。

## 硬约束

- 不创建、不修改外部业务对象，不保存外部业务阶段状态。
- 无权内容不得进入召回结果或调试轨迹。
- 最终证据必须回到冻结资产与来源定位器核验，数据库投影不是事实源。
- 请求缺少决定适用性的关键维度时返回补问，不生成泛化结论。
