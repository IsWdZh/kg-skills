# kg-coordinate：多形态协同与一致性校验

## 输入 / 输出

- 输入：`50-知识资产/`、`10-解析文档/`
- 输出：`50-知识资产/_协同/协同校验报告.md`

## 执行步骤

### 1. 机械校验

```bash
python scripts/check_links.py <工作区目录>
```

必须全部通过：

- 所有`文档编号#pNNN`或区间锚点真实存在。
- 问答对、Wiki、图谱引用的知识块 ID 存在，含`KC-...-001/002`简写展开。
- 包清单和资产中的 Markdown 文件链接可解析。
- 不存在`KC-...-...`、`待补`、`TODO`等占位引用。
- 知识块、问答对、图谱规则均有条目级来源，不能只在文件头写“来源”。
- 已发布包引用的 Wiki 不得仍标`已生成待审`。
- 已设「来源文档」映射表的知识包，该表必须覆盖本包所有被引用文档编号（含共性知识底层来源）；缺失即服务端无法把编号还原为文件名。旧格式包（无映射表）只提示待升级，不阻断。

任一失败即退回 `kg-produce`，不得通过人工口头说明绕过。

### 2. 语义校验

逐项核对并写入报告：

| 类别 | 检查项 |
|---|---|
| 统一挂接 | 资产 ID 与场景、地区一致；共性知识只引用不复制 |
| 形态协作 | QA→KC→原文链完整；Wiki 章节与图谱规则可互证 |
| 适用范围 | 地区、对象、时间在各形态中一致 |
| 冲突口径 | 知识块、Wiki、问答对、服务约束的冲突提示一致 |
| 数字一致 | 额度、年限、比例、日期逐项回查原文锚点 |
| 权限与时效 | 不向公开包投放内部或受限来源；未知/过期来源带提示 |

### 3. 图谱结构校验

- 直接关系只允许一个已定义实体指向另一个已定义实体。
- `E01/E02`、`E05+E07`、自然语言条件不能作为直接实体边。
- AND/OR、例外和多条件结论必须建模为规则节点或关系陈述节点，并关联来源知识块。
- 图数据库导入不应“猜测”复合表达式的实体含义。

### 4. 组包结论

报告按地区版本给出：`可进入试跑组包`、`可进入生产组包`或`退回修复`。存在待人工确认项、来源/权限缺失或未核实冲突时，只能进入受限试跑，不能标为生产发布完成。
