# kg-scenario-map：全局业务图与单元场景

## 输入 / 输出

- 输入：`20-打标结果/`
- 输出：`30-业务图与场景/` 下 6 件：人工边界配置、候选单元场景清单、单元场景目录、全局业务图、地区版本映射、场景覆盖盘点

## 执行步骤

### 1. 人工边界配置（先于一切候选生成）

写 `人工边界配置.md`，确认知识域、服务目标、可独立治理发布的最小单元和不可作为场景的属性维度。外部应用的项目阶段、任务和审批不得成为知识场景。

### 2. LLM 生成候选场景

以知识主题和内容单元标签为种子，逐个评估：是否独立被检索/提问、是否有独立规则与证据、能否独立治理发布、能否独立授权、是否只是地区/对象/时间属性。

每个候选输出：候选名 / 涉及文档 / 拆分理由 / 建议独立治理（是/否/待确认）/ 建议治理方式 / 置信度。**同时识别共性知识**（横切多场景的网点、法条、通用约束、支撑业务）→ 建议否决为场景、归共性知识。

批量生成候选时，`scripts/gen_scenarios.py`只读取工作区`治理参数.json`中的已确认词表、适用版本配置和`20-打标结果/文档级打标.md`；不得在脚本内维护行业、地区或来源清单。

### 3. 人工确认（人工确认关卡②）

确认动作四种：**采纳**（分配编码）/ **合并**（并入某场景作特殊规则，写明去向）/ **否决**（写明归宿，常见为共性知识）/ **改名**。编码在确认后按顺序分配，被合并/否决的候选**不占用编码**。结果固化为 `单元场景目录.md`（状态: 已确认 + 日期），每场景登记：编码/场景名/地区版本/状态（待治理/治理中/已治理）/治理方式。

### 4. 全局业务图 + 地区版本映射

- `全局业务图.md`：呈现知识域→主题→服务单元→适用版本，并关联证据、方法和案例覆盖；
- `地区版本映射.md`：对进入治理的场景做三层映射——场景 → 地区版本 → 来源文档（含依据范围与时效基准）；多文档合成的版本逐一列出各文档贡献的章节锚点。

### 5. 场景覆盖盘点（缺口是一等公民）

输出地区覆盖矩阵（场景 × 地区，✅/❌/⚠️）+ 重点缺口清单（影响 + 建议处置）。常见缺口类型：某地区无专门文档（→服务降级+补采建议）、长文档部分未转写（→按需补转）、文档时效风险、单地区场景跨地区误答风险。**缺口不掩盖、不编造，显式进入后续治理决策。**
