# kg-package：知识包组装与发布

## 输入 / 输出

- 输入：`50-知识资产/`、`50-知识资产/_协同/协同校验报告.md`、`40-治理配置/`
- 输出：`60-知识包/{场景}/{地区}/v{版本}/`下的包清单与`资产/`快照、审核清单、质量报告、发布记录，以及`80-知识库导出/`

模板见 [references/templates.md](references/templates.md)。

## 核心约定

- 发布、回滚和服务路由的最小单位都是“场景 + 地区 + 版本”。
- `50-知识资产/`是可编辑治理区；已发布版本必须复制为不可变快照，不能继续引用可变文件。
- 每个发布版本必须保存逐文件 SHA-256 和包指纹；同版本内容变化必须报错，不能静默覆盖。
- Markdown 快照是发布事实源；JSONL、SQLite、PostgreSQL、Neo4j、向量索引均是可重建投影，禁止在数据库内手工修正文义。
- 待确认项、未知访问范围或未核实冲突存在时，动作只能写`受限试跑发布`，不能写`生产发布`。

## 执行步骤

1. **组装包清单**：记录场景、地区、档位、版本、状态、时效、资产、共性知识、适用范围、调用顺序、来源文档和特殊服务约束。其中**来源文档须为「编号 → 文件名/标题」全量映射表**（含共性知识 GJJ-CK-xx 的底层源文档），文件名/标题取自 00-文档台账/台账.md，确保服务端只读本冻结包即可把引用编号还原成文件名，不依赖工作区台账。
2. **人工审核**：核对资产完整性、溯源、适用范围、数字、跨地区差异、冲突、缺口、权限与敏感信息。推理档还需核对规则、Wiki 和流程图一致性。
3. **质量报告**：输出解析完整率、覆盖率、来源引用率、冲突处理率、权限完整率、时效风险和可回滚性。结论为`允许生产发布|允许受限试跑|退回治理|建议升级治理方式`。
4. **冻结版本**：运行：

```bash
python scripts/snapshot_packages.py <工作区目录>
```

脚本把包清单引用的资产复制到当前版本目录`资产/`，将链接改为本地快照，并写逐文件哈希与包指纹。重复运行只能验证一致性，不能改写已冻结版本。

5. **发布登记**：登记时间、版本、动作、审核依据、回滚点、当前有效版本和发布级别。服务路由只认当前有效且未撤回的版本。
6. **导出服务投影**：运行：

```bash
python scripts/export_kb.py <工作区目录>
```

输出`交换态/*.jsonl`、`知识库.db`、`导入Neo4j.cypher`和`导出报告.md`。导出必须读取冻结快照，而不是读取`50-知识资产/`当前工作副本。
7. **发布后验收**：调用 `kg-serve` 执行全部服务分支测试；失败则撤回当前版本并登记原因。

## 存储选型

- 单人或试跑：SQLite + FTS5 trigram 足够承担元数据、知识块、问答对、审计和中文关键词检索。
- 多人生产：关系核心升级为 PostgreSQL；语义召回有明确评测收益时再启用 pgvector。
- 图数据库（Neo4j/NebulaGraph）只在路径查询、规则依赖、影响分析成为高频需求时部署；它不是知识图谱的事实源。
- Wiki 正文继续保留 Markdown，关系库只保存页面元数据、版本、权限和索引字段。

## 可选投影加载脚本（外部数据库就绪时）

连接参数在各脚本顶部配置；全部为幂等可重建投影，重跑=清空重建，不回写治理态。

```bash
python scripts/load_pg.py <工作区目录>          # PostgreSQL：知识数据（知识块/问答对/Wiki及支撑表）+ pgvector 向量（知识块/问答对/Wiki三类，bge-small-zh-v1.5）
python scripts/load_pg.py <工作区目录> --no-embed   # 无嵌入模型环境跳过向量
python scripts/load_nebula.py <工作区目录>      # NebulaGraph：实体/规则/关系三元组（复合表达式建关系陈述节点，不伪造实体边）
python scripts/demo_vector_search.py <工作区目录> "问题"   # 向量语义检索
```

约束：①必须使用独立数据库/图空间（如 kg_gjj_trial），不与目标服务器既有库混用；②嵌入模型缓存于 `工作区/_scripts/_models/`，离线可用；③答案生成仍须回到冻结包资产与锚点核验，数据库仅作检索与计算。
