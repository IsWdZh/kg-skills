# kg-verify：只读知识与一致性校验

## 输入 / 输出

- 输入：外部对象快照、业务版本、证据映射、规则集版本和权限上下文。
- 输出：校验报告 JSON/Markdown，按`blocker|warning|suggestion`分级。

规则格式见 [references/validation-contract.md](references/validation-contract.md)。确定性试跑：

```bash
python scripts/verify_snapshot.py --snapshot snapshot.json --rules rules.yaml --output findings.json
```

## 校验层次

1. 字段：必填、类型、枚举、格式、编号和空值。
2. 来源：证据覆盖、定位、时效、地区、版本和知识角色。
3. 对象：命名、颗粒度、职责、输入输出、结果和重复。
4. 结构：树覆盖、流程断点、死循环、孤立节点和异常分支。
5. 关系：问题、需求、改革、场景、流程、能力、数据、建设和验收的覆盖与孤立项。
6. 语义：病句、歧义、术语冲突、前后矛盾和潜在遗漏。
7. 历史比较：与已发布规则、案例和通过版本的差异及风险。

## 硬约束

- 快照只读；报告不得包含补丁、写回命令或业务审批结论。
- 每个问题包含规则 ID、对象 ID、严重级别、证据、说明和修复建议。
- 规则必须声明适用条件和例外；多对多业务关系不得误写为一对一硬规则。
- 人工豁免由外部应用记录，知识平台只接收豁免反馈用于规则评估。
